# Workspace UI styles

The workspace follows the toolbar's quiet visual language: neutral surfaces, fine borders, compact rounded controls, and restrained hover and selection feedback. Existing keyboard behavior, accessible names, and loading states belong to the controls and must survive visual changes.

## Shared foundation

`src/style.css` is the entry point. It imports the foundation and feature styles from `src/styles/` in dependency order. Keep feature layout rules in the corresponding module rather than appending overrides to the entry point. Responsive rules follow each module's base styles, from wider to narrower breakpoints.

`tokens.css` defines light and dark semantic colors and derived UI tokens. Use `--bg`, `--side`, `--panel`, `--text`, `--muted`, `--line`, and `--accent` for surfaces and text. Use `--success`, `--warning`, and `--danger` for meaning. Wallpaper presets override the semantic palette, so controls should use these variables instead of literal colors or the removed legacy color aliases.

Shared geometry and feedback use `--ui-radius-*`, `--ui-control`, `--ui-field-height`, `--ui-hover`, `--ui-press`, `--ui-selected`, `--ui-focus`, and `--ui-shadow-*`. Standard icon controls are 36px, fields are 40px, and their usual corner radius is 10px. Keep existing compact variants where the layout needs them. Avoid adding decorative shadows or movement to ordinary rows and buttons.

The composer intentionally retains its original compact bordered controls, resource/usage cards, native icon hints, and animated reasoning accents. Its `--composer-*` palette is centralized in `tokens.css` and scoped to the composer and model popover, so it can keep the original blue light/dark appearance while other surfaces follow the newer toolbar design. Custom wallpaper themes replace this palette with semantic theme colors. Keep the composer rules together in `composer.css`.

## Controls and surfaces

- Use `IconButton` for shared icon actions. Supply a meaningful `title`; it provides the accessible name and compact tooltip. Add `description` when an action needs explanation.
- `Tooltip` coordinates pending and visible tips across the app. Preserve pointer delay, immediate keyboard display, Escape dismissal, and viewport clamping. Connection details retain their richer status card.
- Use `Select` for custom dropdowns, and preserve its keyboard navigation and disabled state.
- Use `Modal` and `ActionDialog` for dialogs and confirmations. Preserve their focus management, inert background, busy state, and cancellation behavior.
- `UserInputRequests` automatically opens Codex questions in a shared `Modal`, including requests from other conversations or child threads. Do not filter them by the selected conversation or bury the form in the composer. Closing defers the dialog and preserves drafts; its notice reopens it. Native `item/tool/requestUserInput` answers use the original JSON-RPC request ID so the paused turn resumes. CLI asynchronous questions arrive as `agentMessage` items with `delivery: "async"` and structured `questions`; the server adapts that metadata to the same dialog with its own `web:async:` ID. Their answers are user input sent through `turn/start`, which appends to running work or starts a follow-up after completion; never reply to the already-completed tool call as JSON-RPC. Async dialogs survive normal turn completion/start and reconnect, and clear on answer, interruption, failure or process loss. Async notices describe a request for supplementary information rather than paused work. Never infer questions from assistant prose.
- `SettingsPanel` owns the settings navigation and consistent section headings; appearance editing remains in `Appearance` with its current-device restriction.
- Conversation mode (execute/plan) is configured in general settings. The composer retains attachment, permission, and model controls.
- General settings do not expose the user-container network access checkbox or its execution-environment explanation. Retain the model, reasoning effort, conversation mode and immediate-save feedback.
- New-conversation suggestions use a compact icon/text/arrow grid. Keep titles and descriptions together with the existing 13px/11px desktop typography (12px mobile titles); retain descriptions when the editor is open and switch to one column when the chat container is narrow.
- `components/BrandMark.jsx` is the shared star/dew/valley mark: the home hero uses 64px, the login/register card adapts between 36–56px with viewport height, and sidebar and startup branding use the simplified 24px version. The auth header uses the miniature geometry at 26–30px. Its SVG owns the rounded gradient tile, derived from `--accent` with a fallback; do not add a second background, rounded container, shadow or hover effect. Full-size marks only animate the small star and dew, with reduced-motion overrides; miniature marks remain static. `public/favicon.svg` uses the matching simplified star/dew geometry with fixed colors, referenced by `index.html` and copied into the Docker build through `public/`. The completion-notice favicon uses the same fixed-color mark underneath its existing count badge.
- The sidebar user row has two sibling buttons: the avatar/name area opens personal account settings, and the outlined gear opens general settings. Retain the original sidebar typography: 12px/500 for the username, 9px for the role, and 12px for avatar initials. Keep the circular avatar, truncated username, and role badge together; superadmins use the accent, admins use success, and members use muted tones. The avatar dot shares the toolbar's socket status (green when connected, yellow while connecting/reconnecting, red when disconnected/expired); include the status in the profile button's accessible name.

General settings display a shared optimistic draft and persist through `createSettingsQueue()` in `shared/settings-save.js`. Requests are serialized, unsent edits are merged, and rejected fields revert to confirmed values while later changes continue saving. The queue belongs to the workspace so closing/reopening settings retains pending edits; composer settings use the same queue. Preserve stable controls and the close button during saves.

`Auth.jsx` owns the login/register presentation and reuses the existing API helper, session callback, username pattern, password limits and conditional invitation requirement. `auth-screen.css` scopes the reference's translucent blue card, sky, stars and SVG waves to the unauthenticated screen; `auth.css` retains the workspace startup/welcome styles. The sea preserves the reference's three distinct wave paths, waterlines, opacity, opposing flow, bobbing, theme-specific sheen and 38 randomized glints. Generate decorative positions once so typing and mode changes do not restart or relocate the reflections. Login and registration share a keyboard-accessible tab group, labeled fields, password visibility control and the existing persisted theme. Keep pending mode changes disabled and retain inline server errors. Height breakpoints compact spacing and switch the hero to a horizontal layout; at 600px and below, redundant switch text and the decorative footer are hidden while both mode tabs remain available. Use normal document flow and natural scrolling for very short windows, zoom and long errors rather than cropping controls. Decorative animations respect reduced motion and backgrounds are removed in forced colors.

Shared dialogs restore the 4px backdrop blur, 220ms panel entrance with translation/scaling, 180ms exit, original shadows and animated composer glow. Settings sections use the original short content entrance. `Select` finishes entrance animations on its ancestors before measuring a fixed dropdown, so opening a menu during the animation cannot shift its coordinates. Preserve reduced-motion overrides. `Modal` owns initial focus before the first paint and uses `preventScroll`; action dialogs provide their intended input/cancel ref instead of focusing twice. Capture menu triggers before they close and restore focus after the portal leaves the DOM, unless a new dialog has taken over. Keep the close control in place, disabled during saves, so the heading does not reflow. Exit callbacks share `DIALOG_CLOSE_MS` with the CSS duration, including reduced-motion handling. Unchanged conversation turns remain memoized.

The Browser settings page checks WebGL rendering once per workspace mount and on explicit recheck, releasing its temporary context immediately. Known software renderers or unavailable WebGL produce a dismissible session-only reminder after welcome; masked or unrecognized information stays unknown, and a recognized GPU means only GPU-backed WebGL, not confirmation of the browser's acceleration switch or CSS compositor. No renderer details are stored or sent to the server. The guide gives desktop Edge/Chrome settings addresses to copy (ordinary websites cannot open these internal URLs), tells users to enable graphics acceleration if disabled, save edits and restart the browser. A page refresh cannot apply the changed browser setting. Mobile and unrecognized browsers get generic instructions. Source references: [WebGL renderer privacy limits](https://developer.mozilla.org/en-US/docs/Web/API/WEBGL_debug_renderer_info), [Edge graphics acceleration setting](https://learn.microsoft.com/en-us/troubleshoot/microsoft-edge/performance/edge-high-cpu-memory), [Chrome graphics acceleration and restart](https://support.google.com/a/users/answer/9282978?hl=en).

Monaco and xterm cannot consume CSS expressions such as `color-mix()`. Read their palette through `appearanceColors()` in `appearance-runtime.js`, which resolves theme values to concrete hex colors. Keep the editor selection distinct from its quiet current-line highlight.

## Visual verification

Project code keeps file IO, uploads, save/conflict checks, and selection actions in the existing workspace callbacks. `ProjectFiles` owns the presentation and the local `.meta` visibility preference; `CodeEditor` owns cursor/indent/language display so cursor movement does not rerender the workspace. The status, save button, and dirty tab all derive from the same content/original comparison. Show actual model indentation rather than forcing a different editing behavior.

The reference class mapping is `.cp-header` → `.editor-title`, `.cp-explorer` → `.file-explorer`, `.cp-ex-head` → `.explorer-heading`, `.cp-row` → `.file-row`, `.cp-tabs` → `.editor-tabbar`/`.editor-tabs`, `.cp-crumbs` → `.file-toolbar`, `.cp-save` → `.save-file`, and `.cp-status` → `.editor-status`. Use 46/38/30/26px bars, 30px tree rows, 16px depth steps, and theme-derived editor syntax variables. Monaco gets resolved hex colors through `appearanceColors`; do not add CodeMirror or fixed light-only palettes.

Desktop explorer width defaults to 268px and uses the existing persisted drag/keyboard separator with 200–480px bounds, limited by available editor space. Phones retain the narrower responsive bounds. Header menus must stay above the editor and within the panel. Keep new-file creation in More, all three upload routes in Upload, and the complete existing file row actions and multiselect controls. A compact row below the heading groups file search and the persisted sort selector: name, modification time and creation time, each ascending or descending. Apply the order within every folder, keeping folders first and unknown dates last. Creation dates come from filesystem birth time; do not substitute metadata-change time when unavailable.

Ctrl+P / Cmd+P opens the project file picker from the workspace, including Monaco and a closed code panel. Show filenames with relative paths, prioritize name matches and support fuzzy/path queries. Up/Down chooses a result, Enter opens it and Escape cancels; preserve unsaved tabs. Choosing a result focuses the loaded editor or image canvas after the picker closes, while cancellation restores the previous focus. Opening the picker shows only its search input, without building an index, listing files or showing a result count. Start matching and progressive lazy-directory indexing only after non-whitespace input. Clearing the query immediately hides results and aborts indexing; closing or changing projects also aborts obsolete requests. Exclude every dot-prefixed directory and its descendants at all depths from both indexing and results, while allowing dot-prefixed files in ordinary directories. Search inventory requests use excludeHidden=true so the server skips these subtrees too; the regular explorer retains its existing visibility. Keep a retry for incomplete indexing and cap rendered matches at 80 with a refine-query hint. Existing modal focus trapping and restoration apply. Other dialogs retain their shortcuts. The editor empty state advertises both file search and save.

Check default light and dark modes and a saved wallpaper preset. Review desktop, 390px, and 320px layouts, including long labels, dropdown edges, modal scrolling, and composer controls. Exercise hover, focus, selected, disabled, and busy states. Preserve reduced-motion and forced-colors rules; distinguish source inspection from testing those system settings in a browser. Use synthetic accounts and data for interactive checks that change settings or files.

The editor title groups fullscreen/restore and close controls on the right. Webpage fullscreen keeps the editor mounted, hides the surrounding workspace and preserves models, unsaved content, cursor and explorer width. Escape restores the layout after menus, dialogs and editor commands have handled it; closing the editor resets fullscreen. Keep the mobile sidebar focus trap and main-content inert state inactive while the editor fills the page.

The explorer hides checkboxes and the bulk action bar on desktop. Keep “资源管理器” for zero or one selected item; at two or more, replace it in place with a clear button and “已选 N 项”, including narrow explorer widths. Tree selection is independent of the open editor: an ordinary click selects the file or folder with the stronger background and left accent bar, replacing the previous tree selection. Opening a folder keeps the editor content and active tab. Other selected group members use a lighter background and default text colors. Selecting an editor tab, including the already active tab, selects its tree entry again. A file load completing while focus remains in the tree must not take selection back from another row. Use Ctrl/Cmd-click to toggle rows, Shift-click for visible ranges, and context menus for single or grouped actions. Plain Up/Down moves tree selection without opening a file; Ctrl+Up/Down moves focus only, and Shift+Up/Down extends the visible range. Clicks on blank space or outside the tree clear its selection and highlight; file action menus, confirmations and selection controls keep their targets. At 800px and below every visible row keeps a checkbox and the bulk action bar remains available with its count. A 500ms touch/pen hold opens the same menu; movement beyond 8px cancels it. Keep the ellipsis and Shift+F10 as alternative entry points.

Editor tabs reveal the active file on open (including reopening the current file), selection and resize. Overflowing edges fade into the tab strip; the file-count dropdown lists every open path and its unsaved state. Wheel, horizontal trackpad and touch dragging navigate the strip. At code widths of 260px or less, file actions occupy a second row to preserve readable tabs. Hide native scrollbars globally while preserving scrolling and Monaco/xterm custom sliders; do not restore per-component native scrollbar overrides.

Tab right-click, Shift+F10 and touch/pen long-press open the shared custom menu without activating the target tab. Offer close, close others, close to the right, close saved, close all and copy relative path; disable empty target groups. Middle-click closes only the pointed tab and prevents native autoscroll. Every close route shares one operation: prompt once for all dirty targets, cancel the entire group without partial closing, reject edits changed since approval, and preserve untargeted tabs. Closing the active tab chooses the nearest remaining tab on the right, then the left; closing a background tab keeps the current file. Restore keyboard focus after a closed tab leaves the DOM. Closing tabs never deletes project files.

Explorer and code menus share the portaled, viewport-clamped `ContextMenu`, semantic colors, keyboard navigation and focus restoration. Contextual creation is relative to a folder or the clicked file's parent. Group downloads use one authenticated, CSRF-protected POST to the project download route and retain project-relative ZIP paths; single downloads keep the existing GET behavior. Deletion retains size/fingerprint confirmation and dirty-file protection. Code clipboard edits keep Monaco undo stops, reject stale model versions and leave content intact when clipboard access fails or contains no text.

Project uploads accept OS file drops across the explorer and editor, including Monaco, while preserving ordinary text drags. The drop overlay uses semantic colors and does not intercept pointer events. Folder imports retain hierarchy and empty dropped directories, stream files through browser workers at DEFLATE level 9, then use the existing binary WebSocket channel and validated server extraction. Keep the 128 MiB browser folder byte limit explicit; drain directory readers until they return an empty batch ([directory API](https://developer.mozilla.org/en-US/docs/Web/API/DataTransferItem/webkitGetAsEntry), [streaming compressor](https://github.com/101arrowz/fflate/blob/master/docs/classes/AsyncZipDeflate.md)).

File and directory entry counts use the shared role policy in `shared/file-limits.js`: superadmins have no application-level entry-count cap; members and ordinary admins may process 100,000 entries, counting directories too. Apply it consistently to folder scanning/compression, upload preflight, extraction, file-tree reads, downloads, cleanup inventories and turn snapshots. Server decisions use the persisted account role, never a requested role or count limit. Keep byte quotas and path/link/CRC validation independent; report duplicate ZIP paths separately from count limits. Browser archives with at least 65,535 entries add ZIP64 end records so larger folders retain every entry ([ZIP specification, sections 4.3.14–4.3.16](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)). Browser output remains below 4 GiB because individual offsets use ZIP32; larger output requires a manually prepared ZIP64 archive.

`UploadFeedback` displays a compact card inside the editor, falling back to the floating card when the editor is closed or showing changes. Show stage-specific progress and numeric percentages for measurable compression/transfer/extraction work; unknown directory counts and conflict decisions use an indeterminate state. Keep file names, byte counts, compression savings, cancellation, semantic progressbar attributes, reduced-motion and forced-color support. The shared modal offers skip, overwrite and cancel for all same-path files in the batch. Direct file selections are checked before transfer; archive conflicts retain the uploaded spool for a finish retry without retransmission. Existing directories merge; file/directory type collisions are skipped rather than recursively removed. Validate the entire archive before publication and preserve rollback of overwritten files if publication fails.

The archive picker and archive-only file drops share `shared/archive-formats.js` with the server: ZIP, 7Z, RAR, TAR and gzip/BZip2/XZ/Zstandard TAR variants (including short aliases) are case-insensitive. Label the action “上传压缩包并解压”; ordinary file upload retains archive bytes. Folder packing and downloads still use ZIP. Native readers only stream data; the application validates and writes each regular file itself. Never let native extraction write directly into a project or restore archive permissions, links, owners or special entries. Reject encryption, split archives, unsupported methods and sparse TAR files with a useful error.

Image loading skeletons use selectors more specific than generic `.skeleton` and its `nth-child` width rules: keep the loading label centered and the overlay exactly within the reserved frame. Once loaded, image frames and preview buttons fit the actual image dimensions, bounded by the available width and height. Do not stretch the background to the chat column for small or portrait images. Preserve native lazy loading, load failure/retry, eager modal previews and image aspect ratio.

Project image previews support Ctrl+wheel zoom around the pointer, with a non-passive listener preventing page zoom only over the preview canvas. Buttons zoom from the current fitted size; Fit and Original Size remain available. Use a padded stage so both edges of enlarged images remain reachable, and capture the primary pointer for left-button panning with grab/grabbing feedback. Ordinary wheel scrolling remains native. Reset the view on file changes and release gestures on pointer cancellation; loading and error states keep zoom controls disabled.

Conversation opening reads the latest 8 turns first, in chronological display order, then fetches older turns in background pages of 16. Keep older data out of the rendered message list until upward scrolling or “查看更早记录” reveals 8 more turns. Use an ID boundary so incoming live turns do not hide the user's reading position. Thread resume excludes full turn history; metadata reads and automatic title generation also avoid full-history hydration. Preserve live items when merging overlapping pages, abort obsolete requests on thread/project changes and unmount, and offer background retry without disabling the composer. `useConversationScroll` follows the bottom only while the reader stays near it; otherwise it preserves a visible turn and its offset through prepends and content resizing. Disable native scroll anchoring and estimated turn heights so they do not compete with this position handling.
